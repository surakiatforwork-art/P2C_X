# P2C_X — ระบบชื่อเล่นและสิทธิ์ใช้งาน

หน้าแอดมิน: https://p2cx-control.vercel.app/admin/

ชีต: https://docs.google.com/spreadsheets/d/1ZbfSoXAKc5ky9kS8UFC-lCpL_p7Tyksqa6_T0GW5QDM/edit

Apps Script ใช้ deployment URL ที่เจ้าของส่งให้ในแชท (บันทึกใน Vercel P2CX_SHEETS_URL) และผูกกับชีตนี้โดยเฉพาะ

## วิธีใช้งาน

1. ผู้ใช้ติดตั้ง APK แล้วเปิด P2C_X กรอกชื่อเล่น 1–40 ตัวอักษร และยืนยันชื่อครั้งเดียว
2. เครื่องใหม่ได้รับสถานะ approved อัตโนมัติหลังลงทะเบียนสำเร็จ ผู้ใช้เดิมที่ pending จะได้รับอนุมัติในการตรวจสิทธิ์ครั้งถัดไป
3. แอดมินเข้าเว็บด้วย Google บัญชีที่อนุญาตเพื่อจัดการชื่อและระงับสิทธิ์ เครื่องที่ blocked จะไม่ถูกอนุมัติอัตโนมัติ และสวิตช์ปิดระบบส่วนกลางยังมีผลตามเดิม
4. ผู้ใช้กด ตรวจสิทธิ์อีกครั้ง ได้ทันที หรือรอรอบอัตโนมัติ 12–18 นาทีขณะที่แอปทำงาน
5. เมื่อติดตั้งโมดูลรุ่นใหม่ ให้เปิด target ใหม่หรือรีบูตเพื่อให้ LSPosed โหลดโค้ดใหม่

ในชีต Devices แอดมินแก้ nickname และ status ได้โดยตรง: pending = รออนุมัติ, approved = อนุมัติ, blocked = ระงับ ห้ามแก้ deviceId เพื่อย้ายสิทธิ์ให้เครื่องอื่น ชื่อเล่นไม่จำเป็นต้องไม่ซ้ำ รหัสเครื่องยังใช้แยกเครื่องที่ชื่อเหมือนกัน

ผู้ใช้เปลี่ยนชื่อผ่านแอปไม่ได้ การล้างข้อมูลแล้วลงทะเบียนซ้ำด้วยรหัสเครื่องเดิมจะได้ชื่อและสถานะเดิมกลับมา การเปลี่ยนชื่อผ่านเว็บล้าง cache ทันที ส่วนแก้ชีตตรงอาจรอ cache ไม่เกิน 5 นาที และแอปต้องติดต่อในรอบถัดไป

## ข้อมูลที่เก็บ

- Devices: รหัส SHA-256 ของ Android ID ที่แยก prefix ของ P2C_X, ชื่อเล่น, สิทธิ์, หมายเหตุ, รุ่น/เวอร์ชัน, เวลาติดต่อ
- Settings: enabled เป็น true/false สำหรับสถานะส่วนกลาง
- AuditLogs: การเปลี่ยนชื่อและสิทธิ์โดยแอดมิน
- UsageDaily: ยอดเปิดแกลเลอรี่และยืนยันภาพรายวัน ส่งยอดสะสมย้อนหลังได้ 7 วัน และส่งซ้ำไม่บวกซ้ำ

ยอดยืนยันภาพหมายถึงผู้ใช้กดใช้ภาพและสร้างผลลัพธ์แล้ว ไม่ใช่การยืนยันว่าแอปปลายทางบันทึกภาพสำเร็จ ไม่มีภาพ ไฟล์ภาพ ชื่อไฟล์ content URI พิกัด หรือข้อมูลภายใน target ถูกอัปโหลด

## เครือข่ายและสิทธิ์

ตรวจสิทธิ์เบื้องหลังทุก 12–18 นาทีตาม Full_lock และเก็บกำหนดครั้งถัดไป การเปิดหน้าแอปไม่ยิงตรวจซ้ำถ้ายังไม่ถึงกำหนด กดตรวจเองได้ เมื่อเครือข่าย/เซิร์ฟเวอร์ขัดข้องหรือคำตอบไม่ถูกต้อง ให้คงสิทธิ์ล่าสุด เครื่องใหม่ต้องได้รับการอนุมัติจริงครั้งแรก ไม่อนุญาตจากความผิดพลาดของระบบ

สถานะสิทธิ์แยกจากสวิตช์ผู้ใช้และส่งผ่าน LSPosed RemotePrefs ตัว hook ตรวจทั้งสองค่า Tile หรือเปิดเมื่อบูตไม่สามารถเปิดข้ามสิทธิ์ที่ถูกระงับได้ Token ไม่ถูกส่งเข้า target process

ใช้ Firebase Authentication ของโปรเจกต์ full-lock-control เฉพาะล็อกอินแอดมินด้วย Google และตรวจลายเซ็น ID token ไม่ใช้ Firestore และไม่คัดลอก service-account key ของ Full_lock มาในระบบนี้ ข้อมูลอุปกรณ์ กุญแจฝั่ง API และชีตแยกทั้งหมด การตรวจ token ฝั่งเว็บไม่ตรวจเพิกถอนบัญชีแบบทันที Token เดิมจึงมีผลจนหมดอายุ

## การตั้งค่าและพัฒนา

Vercel ใช้ P2CX_SHEETS_URL, P2CX_SHEETS_SECRET, P2CX_DEVICE_SECRET, P2CX_FIREBASE_WEB_CONFIG โดยเก็บใน Environment Variables เท่านั้น ชีตและโครงการ Apps Script ควรให้สิทธิ์เฉพาะแอดมิน

ไฟล์ .deployment.private.json ในเครื่องเป็นการตั้งค่า deploy ส่วนตัว ห้ามเผยแพร่/commit และถูกกันไว้ด้วย .gitignore กับ .vercelignore เช่นเดียวกับ .env และ .vercel

Apps Script มี DeploymentConfig ซึ่งตั้งค่าสำหรับ deployment ปัจจุบันและไม่อยู่ใน public repository หลังรับคำขอที่ลงลายเซ็นถูกต้อง ระบบซิงก์กุญแจเดียวกันลง P2CX_BRIDGE_SECRET ใน Script Properties

คำสั่งตรวจ backend: npm run test:control

คำสั่งบิลด์ APK: gradlew.bat :app:assembleDebug :app:lintDebug โดยค่า URL เริ่มต้นชี้ไปยังระบบ P2C_X จริง หรือใช้ -Pp2cxControlUrl=... เพื่อเปลี่ยน endpoint สำหรับการพัฒนา

มีรายการ ทดสอบระบบ (QA) ในชีตที่สร้างเพื่อทดสอบ ไม่ใช่ผู้ใช้จริง และอยู่สถานะระงับ

ยังไม่ได้ push GitHub หรือสร้าง release จากงานนี้
